## 问题1：死锁

### 🔴 问题描述
**场景**：进程崩溃，锁未释放
```
进程A: 获取锁 → 执行中 → 崩溃！💥
进程B: 等待锁 → 永远等待 → 死锁
```

### ✅ 解决方案

#### 代码位置
`rate_limiter.py` 第 178-209 行

#### 核心代码
```python
# 1. 锁文件包含时间戳
lock_info = {
    'pid': my_pid,
    'timestamp': time.time(),  # 记录获取时间
    'hostname': ...
}

# 2. 检查时计算锁年龄
lock_age = time.time() - lock_info['timestamp']

# 3. 超过30秒强制删除
if lock_age > 30:
    os.remove(self.lock_file)
```

#### 工作原理
1. **记录时间**：获取锁时记录当前时间戳
2. **检测过期**：每次等待时检查锁年龄
3. **自动清理**：超过30秒自动删除锁
4. **容错处理**：文件已删除的错误被忽略

#### 关键参数
- `30秒`：超时阈值
  - 为什么是30秒？
  - 正常操作 < 0.1秒
  - 30秒足够宽松，避免误判
  - 足够短，不会等太久

## 问题2：并发冲突

### 🔴 问题描述
**场景**：多进程同时操作队列
```
进程A: 读取队列 []
进程B: 读取队列 []  ← 都读到空
进程A: 计算时间 1.0秒
进程B: 计算时间 1.0秒  ← 冲突！
```

### ✅ 解决方案

#### 代码位置
`rate_limiter.py` 第 67-70 行

#### 核心代码
```python
# 文件锁保护整个读写过程
if not self._acquire_lock():
    raise RuntimeError("无法获取文件锁")

try:
    queue = self._read_queue()     # 读取
    next_time = calculate_time()    # 计算
    queue.append(new_request)       # 修改
    self._write_queue(queue)        # 写入
finally:
    self._release_lock()            # 释放
```

#### 工作原理
1. **获取锁**：操作前获取文件锁
2. **保护过程**：整个读写过程都在锁保护下
3. **释放锁**：完成后释放（finally保证）
4. **原子操作**：使用 `O_CREAT | O_EXCL` 标志

#### 关键函数
```python
os.open(file, os.O_CREAT | os.O_EXCL | os.O_WRONLY)
#               ↑ 创建      ↑ 排他      ↑ 只写
```
- `O_CREAT`：创建文件
- `O_EXCL`：排他模式（文件存在则失败）
- 这两个标志组合是原子操作
- 操作系统保证同一时间只有一个进程成功

## 问题3：时间错误

### 🔴 问题描述
**场景A**：系统时间被调整
```
上次请求: 100.0秒
当前时间: 99.9秒  ← 时间倒退了！
```

**场景B**：请求堆积
```
队列中有很多过期请求：
[
  {time: 100.0, created_at: 40.0},  # 已过60秒
  {time: 101.0, created_at: 40.0},
  ...
]
```

### ✅ 解决方案

#### 场景A：时间倒流

**代码位置**：`rate_limiter.py` 第 88 行

**核心代码**：
```python
# 使用 max() 防止时间倒流
next_time = max(current_time, last_time) + self.min_interval
```

**工作原理**：
- `max(current, last)`：取较大的时间
- 如果时间倒流，使用上次请求时间
- 保证时间单调递增

**示例**：
```python
last_time = 100.0
current_time = 99.9  # 时间倒退

next_time = max(99.9, 100.0) + 1.0
         = 100.0 + 1.0
         = 101.0  # 正确！
```

#### 场景B：请求堆积

**代码位置**：`rate_limiter.py` 第 77-80 行

**核心代码**：
```python
# 清理超过60秒的过期请求
queue = [
    item for item in queue
    if current_time - item['created_at'] < 60
]
```

**工作原理**：
- 每次读取队列时检查年龄
- 超过60秒的请求被删除
- 避免队列无限增长

**关键参数**：
- `60秒`：过期阈值
  - 为什么是60秒？
  - 正常请求 < 1秒完成
  - 60秒足够宽松
  - 超过60秒说明进程崩溃

## 问题4：进程崩溃

### 🔴 问题描述
**场景**：请求写入队列后崩溃
```
进程A: 写入队列 {id: req_1, time: 1.0}
进程A: 崩溃！💥
队列中留下孤儿请求
```

### ✅ 解决方案

#### 代码位置
`rate_limiter.py` 第 77-80 行

#### 核心代码
```python
# 每次读取时清理过期请求
queue = [
    item for item in queue
    if current_time - item['created_at'] < 60
]
```

#### 工作原理
1. **记录创建时间**：每个请求都有 `created_at`
2. **检查年龄**：读取时计算请求年龄
3. **自动清理**：超过60秒的请求被删除
4. **防御性编程**：即使进程崩溃也能恢复

#### 请求格式
```json
{
  "id": "req_12345_1234567890.123",
  "scheduled_time": 1234567891.123,
  "created_at": 1234567890.123,  // 用于检测过期
  "status": "pending"
}
```

## 问题5：文件损坏

### 🔴 问题描述
**场景**：写入时崩溃
```python
with open(file, 'w') as f:
    f.write('{"id": "req_1",')  # 写入一半崩溃！
```
结果：文件只有一半内容，JSON格式错误

### ✅ 解决方案

#### 代码位置
`rate_limiter.py` 第 245-260 行

#### 核心代码
```python
# 原子写入
temp_file = self.queue_file.with_suffix('.tmp')

# 1. 先写入临时文件
with open(temp_file, 'w') as f:
    json.dump(queue, f)

# 2. 原子重命名
temp_file.replace(self.queue_file)
```

#### 工作原理
1. **写入临时文件**：先写入 `.tmp` 文件
2. **原子重命名**：使用 `replace()` 重命名
3. **操作系统保证**：重命名是原子操作
4. **崩溃安全**：如果崩溃，原文件不受影响

#### 流程图
```
开始写入
  ↓
写入 queue.json.tmp
  ↓
原子重命名为 queue.json
  ↓
完成

如果崩溃：
  - tmp文件可能损坏，但原文件完整
  - 下次读取时会忽略tmp文件
```

## 问题6：竞态条件

### 🔴 问题描述
**场景**：多进程同时检测过期锁
```
进程A: 检测到锁过期 (10.1秒)
进程B: 检测到锁过期 (10.1秒)
进程A: 删除锁 ✓
进程B: 删除锁 ✗ (文件不存在错误)
```

### ✅ 解决方案

#### 代码位置
`rate_limiter.py` 第 200-204 行

#### 核心代码
```python
try:
    os.remove(self.lock_file)
except FileNotFoundError:
    pass  # 文件已被其他进程删除，忽略
```

#### 工作原理
1. **尝试删除**：尝试删除文件
2. **捕获异常**：如果文件不存在，捕获异常
3. **静默忽略**：不处理错误，继续执行
4. **结果一致**：无论哪个进程删除，结果都一样

#### 异常处理策略
```python
try:
    # 可能失败的操作
except 预期的异常:
    # 静默处理或记录日志
except Exception as e:
    # 未知异常，需要报告
```

## ✅ 安全保证总结

### ✅ 不会死锁
- **原因**：30秒超时自动清理
- **代码**：`_acquire_lock()` 中的超时检测
- **证据**：即使进程崩溃，30秒后也能恢复

### ✅ 不会冲突
- **原因**：文件锁保护整个读写过程
- **代码**：`O_CREAT | O_EXCL` 原子操作
- **证据**：操作系统保证不会同时成功

### ✅ 不会时间错误
- **原因**：`max()` 函数防止倒流
- **代码**：`wait_for_turn()` 中的时间计算
- **证据**：时间永远单调递增

### ✅ 崩溃可恢复
- **原因**：过期请求自动清理
- **代码**：每次读取时的过滤逻辑
- **证据**：崩溃的请求不会影响后续请求

### ✅ 文件不损坏
- **原因**：原子写入机制
- **代码**：临时文件 + 重命名
- **证据**：写入中途崩溃不影响原文件

### ✅ 竞态安全
- **原因**：全面的异常处理
- **代码**：所有 `os.remove()` 都有异常处理
- **证据**：任何竞态都不会导致崩溃
